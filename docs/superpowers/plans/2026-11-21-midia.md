# Mídia (anexo em postagem e foto de perfil) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Postagens aceitam um anexo (PDF, PNG ou JPG) e o usuário pode ter foto de perfil, com os arquivos guardados em armazenamento S3-compatível.

**Architecture:** Módulo novo `midia` (layout `web/aplicacao/dominio`) com tabela `arquivo` e um adaptador S3. O upload passa pelo backend (`POST /arquivos`, multipart) e devolve um `id`; postagem e perfil guardam só esse `Long`. Leitura por URL assinada de curta duração, resolvida pelos Resources via `midia.MidiaConsulta`. Em dev e testes o Quarkus Dev Services sobe um S3 local; as variáveis de produção só valem em `%prod`.

**Tech Stack:** Quarkus 3.33 (`quarkus-rest` multipart), extensão `quarkus-amazon-s3` + `url-connection-client`, Liquibase, Angular 22 (Vitest, Playwright).

**Spec:** `docs/superpowers/specs/2026-11-21-midia-design.md`

**Branch/PR:** branch `KAN-128-midia-anexo-e-foto-perfil`; o título do PR termina com `(KAN-128)`. Commits seguem `tipo(escopo): descrição (KAN-128)`.

## Global Constraints

- Contrato primeiro: `openapi.yaml` acordado antes de qualquer endpoint (AD-4); `npx --yes @redocly/cli lint openapi.yaml` limpo.
- Limites: PDF até 5 MB (`5242880` bytes), imagem até 2 MB (`2097152`), foto de perfil só PNG/JPG; tipo detectado pelos primeiros bytes (PNG `89 50 4E 47 0D 0A 1A 0A`, JPEG `FF D8 FF`, PDF `%PDF-`), nunca pelo `Content-Type` nem pela extensão.
- Um arquivo por postagem; um arquivo só serve a um uso; só o dono associa.
- Bucket privado; URL assinada expira em 10 minutos (`midia.url-validade-minutos`).
- Variáveis de produção (nomes provisórios, finais só no fim): `ARMAZENAMENTO_ENDPOINT`, `ARMAZENAMENTO_REGIAO`, `ARMAZENAMENTO_BUCKET`, `ARMAZENAMENTO_ACCESS_KEY` (segredo), `ARMAZENAMENTO_SECRET_KEY` (segredo). Nenhum valor em código nem em `render.yaml` (`sync: false`).
- Regras entre módulos (AD-3): `midia` não importa módulo nenhum; `identidade` não importa `midia` (guarda só `Long`); `publicacoes` e `perfil` só importam a raiz de `midia`. `ArquiteturaTest` verde, sem exceções.
- Erros só por `ApiException` (`validacao`/`semPermissao`/`naoEncontrado`/`conflito`); ids `bigint`; `Instant` para timestamps; nomes de entidade/coluna em português; campos JSON em camelCase português.
- Migration por módulo, changeset id prefixado: `midia-001-...`, `publicacoes-003-...`, `identidade-012-...`.
- Front: SCSS só com `var(--uc-*)`; WCAG 2.2 AA; tela nova ganha teste no `e2e/acessibilidade.spec.ts`.
- Teste faz parte da entrega: Service com unitário por `ApiException`; Resource com `@QuarkusTest` (feliz, 401, cada código de erro).

## Review Focus

- Arquivo PNG renomeado `.pdf` (ou `Content-Type` mentindo): rejeitar pelo conteúdo, nunca gravar. Teste na Task 2.
- Arquivo vazio ou sem a parte `arquivo` no multipart: 400 `ARQUIVO_OBRIGATORIO`, sem 500. Task 2.
- Arquivo acima do limite do tipo (e acima do limite de corpo HTTP): resposta no envelope de erro, não página de erro do servidor. Task 2.
- `arquivoId` de outro usuário, inexistente, ou já usado em outra postagem/foto: negado sem vazar a existência. Tasks 3 e 4.
- Nome original com acentos, barras ou aspas: URL e cabeçalhos seguros, nome exibido preservado. Task 2.
- Trocar a foto apaga a anterior; remover a foto volta às iniciais. Task 5.
- Falha do armazenamento (bucket fora do ar) vira erro 500 padronizado e não deixa linha em `arquivo` sem objeto. Task 2.
